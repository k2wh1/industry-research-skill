# 20｜正式研究定稿：有限而严格的交付终点（v2.10）

## 三种状态，必须区分
1. **内部正式研究定稿 FORMAL_RESEARCH_FINAL**：固定研究范围内的核心事实、商业逻辑、九个或其他约定专题、财务模型、重要反证、全文编辑已完成内部核验，所有可行动的重大缺陷修复。允许对不影响现有结论的内部不可得数据做边界披露，直接交付正式 PDF/Word，而不是无限输出 M8/M9 的 STAGED。
2. **独立/机构终审 INDEPENDENT_APPROVAL**：由真正独立于作者的人员或机构审核并批准。AI 自评、多角色扮演和脚本通过均不等于此项。没有实际批准时只能称“内部研究定稿（未获独立审签）”，不能自称券商正式发布报告。
3. **后续滚动更新 UPDATE**：定稿后新增财报、行业价格或技术事实，属于新的研究跟踪任务；新的信息未出现不意味着本期报告不可定稿。

## 五项固定的研究验收
开始时生成 finalization_scope.md，锁定题目、as-of 日期、行业覆盖、核心问题、工作产品、源验证口径和正式验收范围；执行中不得为了及格静默缩减范围。

- source_integrity：所有影响结论的事实和财务数据经过原文查证与复算。不能核实的重要断言应删改、明示假设或限制推理，不能写成官方实测。
- research_depth：用户要求的各高优先级领域深入解释产品、需求、客户付款、竞争、盈利、现金流及适用的资本回报；不要求无法披露的每项产品级 ROIC，但替代模型必须有证据和适用范围。
- judgment_and_falsification：核心判断可由证据推导，给出反方解释、适用条件和能推翻判断的跟踪指标；主报告和专题不矛盾。
- editorial_integrity：数据和图表口径一致，目录页码/中文字体/跨页布局实际检查，主报告与专题分工明确，去除旧版拼接痕迹和来源占位符。
- final_integrated_review：可行动 P0/P1 缺陷为零；每项修复有原缺陷→变更位置→核验记录，最后一次对完整报告而非局部章节复审。

必须执行研究返工，而不是只填审计表；脚本 PASS 不证明作者真的核验了事实。

## 如何判定数据缺口
**CRITICAL**：影响报告已承诺的主要结论、重要指标错误、核心子领域未研究，必须阻断定稿，不允许靠声明“数据缺失”洗白。
**NONCRITICAL**：如 SKU 成交净价、企业内部良率、厂级投入资本不公开，但通过有证据的替代方法形成边界清楚的结论，允许定稿；必须有原因、替代研究、结论范围和正文披露位置。
不能为求通过把 P0/P1 改写成 NONCRITICAL。需要保留原缺陷历史、变更理由与影响审查。非关键数据缺失是“不能得出某个超范围的结论”，不必导致整份已经完成经营研究的报告永久 STAGED。

## 两级验收与合理停止
主目标是正式研究定稿。五项均 PASS，关键引证核实，高优先级专题不留重大缺口，文件可读，则停止无效迭代，并交付正式 PDF、Word、审计和证据包。质量评分只是定位问题，不得通过随意打到90分冒充研究完成，也不得仅因没有90分而无限延期（存在真实重大质量缺陷时仍须修复）。

独立机构签审始终需要真正独立审稿人，不是自动可获得的状态。正常定稿后新的议题放在持续跟踪计划，不再推翻前一份定稿的正常交付。

运行：
    python scripts/formal_final_gate.py --report outputs/research_report.md --acceptance outputs/formal_final_acceptance.csv --gaps outputs/formal_final_gaps.csv --defects outputs/revision_defect_ledger.csv --coverage outputs/industry_coverage.csv --sources outputs/source_review.csv --out outputs/formal_final_gate_result.json

该检查器只检查登记表一致性，实际财务核验、独立实质审阅和机构批准不在检查能力范围内。脚本 FINAL_RESEARCH_READY 是候选条件，不是自动签发。

## 资源边界
用户委托当次能解决的缺陷必须先执行修复；受真实工具、资料或可用执行资源限制时，保留 STOP_LIMIT 和可复现的未完成清单，诚实交付 STAGED；不能因为一句“产品级 ROIC 尚不公开”就把已通过五项验收的报告无限推迟。Skill 不能在回复结束后后台自动工作。
