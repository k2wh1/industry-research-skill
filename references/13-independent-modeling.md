# 13｜独立建模与交叉验证（行业总量/供需/盈利预测时必读）

## 研究模型的任务：提供机制，不是“生成一个看起来合理的数字”

研究模型从问题出发：哪个变量解释收入、订单、利润或现金流变化？该变量如何测量，时滞多长，哪些变化推翻模型？不以预测数字数量或模型复杂度衡量质量。

## 1. 四个层级不得混淆

1. **外部机构预测**：引用的参考基准，不是自己的测算。
2. **校准模型**：为了贴近已知总量而调参，可以帮助合理分配结构，但不能再用同一总量检验“独立准确性”。
3. **独立测算**：主要输入直接来自产品、客户、设备、产能或财报等不同微观数据源；可以与外部总量比较，但仍需要核验输入的独立程度。
4. **样本外检验**：对未参与建模或校准的年份、客户、市场、来源验证；充分说明误差、遗漏和方法适用范围。

“自下而上”和“独立”是不同概念。以总量为约束分配出各设备规模，再加总接近总量，只是**会计闭合/校准**，不是独立验证。即使两个模型使用不同名字的变量，只要关键输入引用同一外部预测，也存在共同来源误差。

## 2. 优先建立两条解释链

### 需求侧

终端需求（使用量/订单）→ 客户新增/更新产能 → 资本开支预算 → 设备支出比例 → 分设备/工艺需求 → 采购、发货、验收 → 设备商收入。

必要时拆成 `新建产能 × 单位产能设备成本 + 技术升级改造 + 存量替换 + 售后升级`；对 HBM / CoWoS / GAA 等，应说明实际工艺量变如何增加设备强度，不能只写“需求增多所以设备增长”。

### 供给侧

公司/产品的台数 × 设备平均售价 × 产品组合 + 服务（单列）→ 厂商分部收入 → 行业合计（按明确覆盖率外推）。

处理二手机、寄售、服务、跨财年/汇率、缺失企业与重复计算；不具备清洁收入/数量拆分时，应主动降低精度，列区间与模型缺口。

## 3. 变量台账与不确定性

- 为每项假设保留证据、计量单位、时期、来源发布日期、历史范围、基准与上下行情景。
- 收入模型拆量、价、结构、汇率、份额；盈利模型拆毛利率、利用率、固定成本、研发、折旧、税、营运资本和资本开支。
- 明确模型中的约束关系（库存、产能、良率、交付周期、市场份额之和、现金流勾稽）。
- 敏感性分析应识别对结论影响最大的 2–5 个变量，而非机械设置任意 ±10%。
- 无历史或原始资料支撑时，只能给假设区间/条件性结果，不得假装为确定预测。

## 4. 发布前独立性声明

创建 `model_manifest.json`（参考模板），记录研究问题、公式、模型文件、输入来源（source/assumption/calibration）、输出口径、校准目标、验证目标和验证期间。

运行：

```bash
python scripts/model_check.py path/to/model_manifest.json
```

如果 `calibration_targets` 与 `validation_targets` 重合，或验证数据已被用于模型输入，却又声称“独立”，则报错。检查器只能检查**显式声明**的重叠，无法从表面字段识别隐蔽的数据依赖；分析师必须自行复核公式、样本外数据和会计意义。

## 5. 模型报告必须呈现

一张驱动树或公式表（带单位）；一个可复算模型文件；历史观察与预测分离；至少一项真实独立对照或明确“未完成独立验证”；差异及原因；假设变动如何改变竞争格局、公司利润和估值。
