# 17｜同任务自主 Execute → Reflection → Revision（v2.7 补充研究覆盖闸门）

## 目标：让 AI 自己完成下一轮，而非要求用户重复说“继续”

本文件适用于正式行业深度、公司覆盖、产业专题、以及对既有长报告的继续修订。简短事实回答、SQL 教学、单项排版编辑不强制套用整套研究流程。

**一次委托就是一次完整的研究执行任务。** “生成 PDF/Word”“写完九个专题”“运行脚本 PASS”“完成第二版”均不是自动终点。已知且可解决的质量问题，由执行者在**当前任务内**修复并重新审查；不能把自主修复的工作转交给用户。

该循环在当前可用工具、数据和响应资源内连续执行；不是离线守护进程，也不能暗示消息结束后仍在后台研究。

## 必须执行的状态机

PLAN → EXECUTE(R1) → AUDIT → REFLECT(R1) → DIAGNOSE → [REVISE → VERIFY → EXECUTE/REFLECT(R2...)] → INTEGRATION QA → HANDOFF

### 1. PLAN｜明确验收，不按页数计成功
- 固定研究目标、主要争议、行业/公司覆盖、as-of 日期、交付物清单、核心财务判断及最低证据要求。
- 为每个专题登记优先级、必需分析层次、可用来源、难以获得的数据、与总报告的依赖。
- 旧稿重构先建立 source → destination 映射，完整保留可核验的独立判断和证据；删除重复不等于删除研究。
- 写出**可判定的验收条件**：核心问题有回答、重大事实冲突为零、重要环节深度≥2/3、重要量化模型可复算、正文无冗余口径解释、文件实际可读。
- 在一项高优先级研究无法取得必要数据时明确可替代的证据和最保守能够成立的结论，不把该事项藏入最终页脚。

### 2. EXECUTE｜写作与核验同步进行
- 研究以“需求 → 供给 → 竞争 → 量价 → 利润与现金流 → 资本回报 → 投资含义”为主线，不以技术名词、公司名单和统计口径汇编为主体。
- 关键事实尽可能使用原始披露。区分 FACT / GUIDANCE / ASSUMPTION / INFERENCE；处理版本、单位、季节性、财年与模型校准。
- 每个重要专题必须说明谁用、谁买、谁付钱、成本构成、为何产生利润、利润能否持续、反例是什么。
- 图表优先承载趋势、量价拆解、利润桥、竞争和情景；不为满足页数或图数量制作同质图。
- 对已有结论和模型进行增量修改时，维护来源/公式/结论的变更映射。

### 3. REFLECTION｜像独立审稿人一样“找错”
初稿形成后应回看**整个报告**，不能仅检查新写的几页。至少覆盖：
1. 核心问题与最终结论是否一一对应？有无“主报告只有几页，专题却极长”的结构失衡？
2. 核心数字能否追到原始来源、时间、统计范围、单位？章节之间是否使用相互冲突的数值？
3. 论证每一跳是否讲明机制和前提？会计恒等式有没有被错误地宣称为因果识别？
4. 是真的比较企业竞争与增量资本回报，还是仅罗列营收、技术参数与公司名单？
5. 统计口径、不可获得数据、免责声明是否反复打断论证？能否合并为一次简短定义和附录？
6. 旧版本拼接痕迹、重复的研究摘要、图表失配、公式缺失、中文字体、跨页表格有无问题？
7. 预测与情景是否使用可追溯参数？没有真实数据是否明确只给条件结论？
8. 对每项重要结论是否提供最强反证、领先指标和利润/估值影响？
9. 每处修订是否导致总报告、专题、图表、结论、证据账本之间出现新冲突？

将每条缺陷登记至 revision_defect_ledger.csv；不要只在最终回复列举缺陷。P0 为重大事实、量纲、来源、推理错误；P1 为重大论证链缺失、研究深度不足、投资误导、重要跨章节矛盾；P2 为不影响核心判断的编辑质量问题。

### 4. DIAGNOSE / REVISE｜从缺陷清单立刻执行
- 按“错误影响 × 可行动性 × 研究优先级”排序，先处理 P0/P1；不要因为文字改写容易就优先润色。
- **每次 Reflection 后不等待用户说“继续”。** 只要存在当前有工具/数据可解决的 P0/P1，就在本次任务中立即修改，记录旧稿位置 → 修订稿位置 → 新证据 → 修复检验。
- 不能删除难题、缩减重要细分市场、凭空补数据，来换取高分；对真正无法取得的数据记录 EXTERNAL_BLOCKED 和影响分析。
- 某模块被外部数据阻断时，在不误导的前提下继续推进**不依赖它的独立模块**；若核心结论仍无法验证则保留 STAGED；但已完成有证据的替代研究并限制推断、仅缺非关键内部数据时，可作为研究完成且充分披露局限。
- 修改要提交新版本/稳定版本引用，不能以“我已改过”代替可检查的修订证据。

### 5. VERIFY / RESCORE｜证明问题真的解决了
- 对每条 FIXED 的 P0/P1，重新查看原始资料、复算必要财务或模型、核对正文及图表对应处，填写 fix_ref / verification_ref。
- 修订后必须再对**全报告**检查跨章节逻辑、数据重复、前后矛盾及排版，并形成下一轮 Reflection；不能只对被改的段落打勾。
- 每轮维护 scorecard / gate / defect ledger，分数提高必须能对应真实修订，不能单靠打分变高。
- 使用 scripts/revision_gate.py、scripts/score_report.py、scripts/run_qa.py；它们只验证已提供材料的结构和算术，不替代一手事实核验。
- 用 execution_cycle.csv 记录每个模块的 R1、R2... 版本链，并运行：
  
      python scripts/autonomous_loop_gate.py --trace outputs/execution_cycle.csv --require-ready --out outputs/loop_gate_result.json

- 此脚本检验“每轮有审阅、修订后有下一轮复审、最终重大缺陷归零或清楚声明阻断”的文档链；**不能证明 AI 真正独立思考或决定 RELEASED**。

## 停止条件（按顺序判断）

1. **正常交接**：全部必要模块无可行动 P0/P1，实证/模型/覆盖门槛通过，原始证据已核对，逐页文件 QA 通过，跨专题结论一致；此时进入 v2.10 五项正式研究定稿审查；实际完成后交付内部正式研究定稿，独立机构终审需另行真实签核。
2. **外部资料阻断**：已尝试合理的公开替代来源，确实缺少必要输入，记录 EXTERNAL_BLOCKED、阻断证据、可能改变的结论、已经完成的替代研究；只有缺口影响本期核心结论时交付 STAGED_REVIEWED；非关键且已完成替代研究和报告披露的数据边界不阻止正式定稿。
3. **工具或执行资源受限**：已完成最大可行修订，记录 STOP_LIMIT、尚未修复的问题及其位置、已运行检查及可复现产物；交付明确的 STAGED / PARTIAL，不能宣称终审完成。
4. **迭代收益停滞**：如果连续修订未减少重大问题，停止机械改写并对根因进行一次分析；若原因可解决，应更换研究或验证方法并再尝试；如果不可解决，按 2 或 3 标注限制。不要把“预设三轮”视为自动成功或自动停止理由。

P2 可依照报告用途继续优化，但不得因为同一句式微调无限循环。一次 R1 即已通过所有条件时不强行制造 R2；只要 R1 发现可行动 P0/P1，必须修订并形成下一轮 Reflection。

## 执行记录格式

模板：assets/execution-cycle-template.csv

字段：
- run_id：一次用户委托的任务标识；一个 CSV 只对应一次执行。
- module：主报告或专题编号，如 M00、S01。
- round_id：模块内严格连续 R1、R2...
- draft_ref：本轮检查的版本引用。
- reflection_ref：本轮全报告或模块 Reflection 的可核查定位。
- p0_open、p1_open：本轮审查发现且仍未修复的重大问题数量。
- decision：REVISE / PASS / EXTERNAL_BLOCKED / STOP_LIMIT。
- revision_ref：本轮修订后的**新版本**，REVISE 必填。
- verification_ref：核验报告/源文件定位，所有终止或修订决定均必填。
- blocking_reason：无法解决/资源受限时的具体原因。

每个 REVISE 行之后必须存在下一轮，且下一轮 draft_ref 与该行 revision_ref 完全一致。PASS 只有在 p0_open=p1_open=0 且本轮有完整验收凭据时才能登记。模块级 EXTERNAL_BLOCKED/STOP_LIMIT 不得伪装 PASS；同时必须区分核心缺口与非关键数据限制。非关键缺失经替代研究和披露后应进入边界台账，而不是作为整份研究的永久外部阻断。

### 可复核最小示例（示意，不是真实研究审查）

    run_id,module,round_id,draft_ref,reflection_ref,p0_open,p1_open,decision,revision_ref,verification_ref,blocking_reason
    semi-001,M00,R1,M4.md,review-R1.md,0,2,REVISE,M5.md,verify-R1.md,
    semi-001,M00,R2,M5.md,review-R2.md,0,0,PASS,,verify-full-R2.md,

## 对用户的交付口径

- 交付时只称“已在本次任务完成的事”，附主要修复清单、确切剩余问题、验收状态及可访问的产物。
- 不把“进入下一版”“后续可继续”当作结束已知缺陷的默认选项；已知可修复事项应先执行。
- 不能在没有运行原始事实审查和全文 QA 时宣称“独立终审通过”或“数据完全可靠”。
- 这是一份研究工作流 Skill，不是能够在消息结束后自主运行的后台 Agent；持续定时复核另需用户明确安排自动化服务。

## v2.7｜HIGH 研究没有完成时不能通过外部阻断退出

每轮 Reflection 首先检查全部 `industry_coverage.csv` HIGH 子领域，与 `research_queue.csv` 和缺陷台账交叉比对。若某 HIGH 子领域仍然 partial，却有公开可研究的商业机制、公司对比、市场规模、价格、资产回报或产品体系，不得将它忽略并用其他领域的 ROIC 或利用率不可得当作结束理由。

EXTERNAL_BLOCKED 必须精确绑定阻断模块；其他独立 HIGH 子领域继续执行。优先使用已有公开资料和有效替代指标补足可研究部分。若确实因执行资源耗尽而不得不结束，明确写 STOP_LIMIT 和剩余可执行研究，而不假称资料缺失使研究完成。

停止前运行 `scripts/coverage_stop_gate.py` 及 `scripts/autonomous_loop_gate.py`；两者是有限的文档逻辑闸门，不证明数据真实性或发布资格。

## v2.10｜明确正式定稿终点

对五项实质门槛进行完整核验之后，应当交付正式内部研究定稿，而非因为未来可继续研究、未披露产品级 ROIC 或评分不足满分而无限重新立项。不存在 AI 自动独立审签；参照 references/20-formal-finalization.md。
