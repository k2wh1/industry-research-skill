# 15｜研究图表与专业排版（正式深度报告必读）

## 原则

图表应当**回答一个研究问题或展示一次可检验的比较**，而不是为了让报告更长、更漂亮。每张图需能解释“看到什么—为什么—影响什么”，正文对应位置至少有一句实质分析，不写无信息量的“见下图”。

## 行业深度优先考虑的图形

- 产业链/工艺图：产品在上游、客户与资金路径中的位置。若难画真实比例，标注示意，不伪装定量信息。
- 历史规模：3–5 年分产品或地区市场规模，明确 actual/forecast/历史版本，避免把旧预测画成历史真实值。
- 需求驱动树：终端需求、单位配置、单位设备投资、时滞；明确哪些数据可得，哪些为模型假设。
- 供需/订单/价格序列：价格与开工率、订单与交付期需要时间轴对齐，不暗示存在没有证据的相关性或领先关系。
- 竞争地图：各产品线核心供应商、份额区间、客户验证阶段；份额口径不一致时不能绘制精确饼图。
- 多年财务：毛利率、营业利润率、研发强度、Capex、ROIC、FCF，确保统一会计口径。
- 预测/敏感性：基准和边界假设、敏感性范围、历史回测误差。不要显示没有可追溯输入的精确概率。

**不是强制“至少 N 张图”。** 输出 `figure_plan.md`，每个关键争议至少评估是否有合适的图形；若研究支持，优先使用上述有效图表；拿不到数据时注明缺口，不能造图。

## 每幅图的审计信息

`figure_manifest.csv` 应含 `figure_id,path,title,period,unit,source_ids,research_question,key_message,limitations`。图内或图注须有：图号与标题、单位、期间、来源（原始/作者测算）、预测或估计标记、必要注释。缺少原始来源不能直接填“作者整理”来代替。对多来源图注明数据日期和可比性。

运行：

```bash
python scripts/figure_check.py path/to/figure_manifest.csv --report path/to/research_report.md
```

检查文件是否存在、图表元数据及报告引用是否完整。**脚本不检验图像中的数字、图形是否失真或中文字体能否正常显示。**

## 格式审查

- Markdown 做可复算与版本管理；正式发布为 DOCX/PDF 时必须实际渲染并逐页检查。
- 中文字体嵌入/替换、标题层级、跨页表格、表头重复、图中文字拥挤、脚注过密和行间距要逐页查看。不要直接把原始 Markdown 的宽表硬转成 Word。
- 正文优先用图形代替重复性数值罗列，技术流程图不能代替对业务因果的解释；同一图不在摘要和各章节重复渲染。
- 只在图表确实支撑结论时安排视觉位置，不为完成页数增加装饰插图。
