# 12｜数据审计与口径一致性（研究建模和正式发布前必读）

## 核心原则

把**原始资料中的数值**与**报告写出的数值**以及**模型计算结果**分开存储；任何一个表、公司、期间和单位都可以追溯。自动算术通过不表示公开原始信息真实，也不表示统计口径合理。

### 1. 三张独立记录

1. `evidence_ledger.csv`：原始证据与可复核位置，保留公司/机构、文件名、发布日期、对应页或表、网址或本地文件、获取日期、原文期间与统计定义。无法读取原始披露时标明二手来源，不得装作已核验。
2. `metrics.csv`：报告/模型使用的数字与来源连接。每行有 `entity + metric + period + period_type + currency + unit + basis + observation_kind + publish_date`；`metric_id` 在报告与模型之间唯一引用。
3. `audit_rules.csv`：需要复算的恒等式和对比关系（加总、差值、比例、同比）。不要只对最后一张表做检查；表格合计、摘要与正文关键值均需进入检查范围。

### 2. 必查的九种错误

- **单位**：亿、十亿、万亿；美元、欧元、人民币、日元；万股/百万股；百分比与百分点。转换只在同一币种、同一计量类型下进行。
- **会计口径**：GAAP/Non-GAAP，合并/单体、毛利率/营业利润率/净利率、经营现金流/自由现金流、资本开支/收购支出；服务收入与设备销售额不能混为分母。
- **期间**：自然年、财年、财季、TTM；同期对比不得使用不一致财年。财年截止日不一致时列出，必要时建立日历化方法。
- **发布版本**：历史实际值、当时预测值、修订预测值不能自动合并成一条“历史数据”。写清统计期、发布日、最新可得版本和研究基准日。
- **分母**：WFE vs 总设备、销售额 vs 订单额、系统 vs 系统+服务、收入份额 vs 台数份额、全球 vs 地区；不确定不得合并。
- **算术**：分项之和、份额之和、收入同比、ROIC 分子分母、毛利与营业利润桥、预测三表和估值权益桥。
- **数据冲突**：同公司/同期间/同统计口径的冲突先记录来源、修订和原因；未解释不能自行选最高或平均值。
- **统计和因果**：毛利率高不等于其所在细分利润池大；存储涨价不直接推出设备订单增长；价格涨跌不直接推出市场隐含预期。
- **伪精确**：主观概率、国产化率、零部件涨价、情景弹性、目标价等精确数据必须有公式或明确“无法核实”。

### 3. 特别针对半导体设备的闸门

- 先确定 WFE、测试、封装、300mm 等分类树，再把每类的统计范围映射到全球总量；残余项不应未经说明为负。不能把部件/服务收入再次加到已包含它们的设备收入中。
- 细分设备中值的总和、总 WFE 值、公司销售额必须在**相同期间且不重叠的产品分类**下才可对账。若九类加总 1185、稿内声称 1165，应报错，不应以“很接近总量”为由忽略。
- 某公司报告中的 1.13 万亿日元与 11.3 万亿日元属于数量级问题，不能靠文字润色修正；需回原始财报核对单位和期间。
- 同一公司在两节报告里的“最近财年营业利润率”若不同，必须查原因；不会因为章节不同就默认为两个口径。
- 引用监管政策时区分已生效法律、正式提案、媒体报道及管理层口头判断。

### 4. 自动检查

在研究输出目录准备 `metrics.csv` 和 `audit_rules.csv`（参考 `assets/` 模板），运行：

```bash
python scripts/data_audit.py path/to/metrics.csv --rules path/to/audit_rules.csv --as-of 2026-11-09
```

脚本能检查指标重复/冲突、单位规范、来源日期越界、加总/差值/比率/同比公式、期间与币种基础一致性。**未提供某条规则时脚本无法发现该类算术错误**；百分比、利润、业务结构还需要人工验证会计含义。`source_org` 与原文数值需要人或具备授权的检索工具核查，脚本不接入财报数据库，也不推断真伪。

### 5. 审计记录与发布阻断

输出 `data_audit_log.md`：错误 ID、原文位置、当前数字、应核验来源、修订结果、影响的结论。`ERROR` 或未解释的重要口径冲突，阻断“数据已审核/报告定稿”的声明。无法获得原始来源时标记 `UNVERIFIED`，且不能以二次重复引用制造证据可信的错觉。
