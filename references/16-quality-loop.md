# 16｜研究质量评分与迭代闭环（Quality Loop）

## 目的和边界

行业研究必须先通过事实审计，才进入人工/协作者的实质评分。评分不是事实验证，不得因为总分高就覆盖重大错误。输出应让下一轮研究知道**修改什么、为何修改、修改后是否真正改进**。

适用：行业速览、行业深度、产业专题、公司首次覆盖、报告改写。按研究任务说明不适用的评价点，但不得随意重新分配总权重以粉饰结果。

## 六步工作流

1. **研究初稿（Draft）**：记录研究对象、范围、版本、研究基准日。保存初稿并保留已有证据和独立内容。
2. **事实与结构 QA（Audit）**：运行原有数据审计、模型审计、覆盖和图表检查；人工查阅原始证据。重大事实冲突记为 FAIL。
3. **八维评分（Score）**：审阅人按 0–5 分对每维分别评分；附可核验定位和不足，写入 quality_scorecard.csv；独立填写 quality_gates.csv。
4. **问题优先级（Diagnose）**：按加权缺口列出前三个重点问题，并结合实质影响安排修订。不得因为文字易改而忽略高影响财务/证据问题。
5. **定向修订（Revise）**：保留原稿版本。修改结构、补数据、重做模型/公司比较，记录原文位置、修改原因、新证据和影响章节，尤其对全行业报告执行内容守恒。
6. **重新审阅（Rescore）**：新增 R2、R3… 评分记录，输出总分、分项变化、仍未解决的硬门槛和下一轮任务；同一版本的分数不得随意覆盖。

建议至多三轮集中修订；若仍达不到门槛，停止无效润色并明确说明缺少的数据/专业验证，而非制造分数改善。

## 八维评分，合计100分

| ID | 维度 | 权重 | 评分时必须检查 |
|---|---|---:|---|
| research_question | 研究目标与核心问题 | 10 | 边界、争议、不同类型的结论与研究目的相称 |
| business_logic | 产业认知与商业逻辑 | 15 | 产品/客户/支付/量价/成本/供需/技术与经营传导 |
| evidence | 数据质量与可核验证据 | 20 | 原始材料、时间与口径、冲突披露、预测与事实分离 |
| modeling | 量化分析与可复算模型 | 15 | 变量、公式、参数、历史对照、独立性和敏感性 |
| competition | 竞争格局与公司经营 | 10 | 同口径对照、份额分母、盈利与ROIC，而非厂商罗列 |
| investment | 投资决策贡献 | 10 | 经营变化如何传至利润、现金流/估值；纯行业研究无需强制目标价 |
| falsification | 前瞻性与可证伪性 | 10 | 情景、反方解释、关键指标、证伪条件 |
| structure | 结构、信息密度与表达 | 10 | 章节分工、去重复、图表规范，保留独立研究证据 |

每维由审阅人给出 0–5 分（允许一位小数）。加权分 = 该维得分 / 5 × 权重，最终相加。0=缺失、1=简介、2=初步、3=有实质分析、4=数据和反证较完整、5=可复核且有独立洞见。分数不是程序对内容自动理解的结果；仅负责计算、校验、比较。

## 六项硬门槛（各轮都要填）

| gate | PASS 前需要的人工或程序证据 |
|---|---|
| source_integrity | 关键披露逐条核对，未知项透明标注 |
| data_audit | 同口径数值、单位、加总、预测版本无重大错误 |
| model_integrity | 可复算模型已审计；没有“校准目标即独立验证” |
| industry_coverage | 高优先级环节实质分析达到应有深度，缺口诚实标识 |
| counterevidence | 核心论点具备反方证据、下行条件及跟踪变量 |
| visual_editorial | 需要时完成图表来源、单位、中文字体和逐页人工检查 |

状态必须填 PASS / FAIL / UNKNOWN，并写证据或原因。任何 FAIL => BLOCKED；存在 UNKNOWN => STAGED。全部 PASS 且总分≥90、各维≥4/5，才可标记 HUMAN_RELEASE_REVIEW_REQUIRED（进入人工终审），**脚本不会直接宣布 RELEASED**。总分未达标=>REVISION_REQUIRED，不等同重大事实错误。

A档≥90，B档80–89.9，C档70–79.9，D档60–69.9，E档<60。档次和发布状态是两个不同概念，例如 A 档仍可能 BLOCKED。

## 最小交付

- quality_scorecard.csv：按轮记录每个维度分数、证据定位、问题、下一步；每轮必须有8项，不重复。
- quality_gates.csv：每轮6项，PASS/FAIL/UNKNOWN、证据说明。
- quality_review.md：分项得分、轮次变化、重点缺口、发布状态。
- revision_queue.csv：按加权改善空间排序的待办；修订实际顺序还应考虑重大影响程度。
- quality_history.json：轮次记录，支持追踪，不替代原始数据和事实审阅。

可以从 assets/quality-scorecard-template.csv、assets/quality-gates-template.csv 填写，再运行：

    python scripts/score_report.py --scores outputs/quality_scorecard.csv --gates outputs/quality_gates.csv --out-dir outputs/quality_loop

脚本只复算**人工登记的评分**、检查条目完整性与门槛状态；不从报告文本自动推断真实性或独立研究深度。质量分达到90不是研究完成的证明。

## 防止刷分和循环自证

- 对比R1/R2分数时必须列明修改证据，不接受仅改写评价文字就提高实质维度。
- 遇到付费/未公开资料不要通过估算冒充实测；记未知，并明确对结论的影响。
- 修改旧稿不能删掉困难问题来提高覆盖得分，应审计独立内容保留率。
- 审阅人、修订者尽量独立；如果同一 AI 自审，注明同源偏差，关键结论请人工复核。
- 不将语言流畅、图数量或字数自动转换成高分。
